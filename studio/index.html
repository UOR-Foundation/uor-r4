    Guide

    How this studio works, the workflows it supports, and what it honestly cannot do yet.

    read me first
    ◈

    An offline-first agent workspace for UOR-R4.

    This page is the Studio: a browser workspace where an OpenAI-compatible agent can help you edit the Studio and API source files, with context you attach explicitly. It is pre-alpha; M1 is the only closed milestone and no useful conversation is established yet.

    01 · QUICK START

    Open Files and start chatting

    1. Open and choose Open folder… (File System Access API).
    2. Click a file to open an editor tab; save edits back to disk with ⌘S.
    3. In , attach the active file as context and describe the task.
    4. Configure an API provider under when a custom OpenAI-compatible endpoint is configured; until then the local engine serves next-token prediction only.
    02 · SESSIONS & CONTEXT

    Build this studio with the agent

    • Sessions live in the sidebar: rename, duplicate, export as JSON, or delete from the row menu (⋯).
    • Context attachments are listed above the composer and are prepended to API prompts only — never sent anywhere at page load.
    • Message actions can copy, insert into the editor, save as Markdown, or retry a prompt.
    • Build task inserts a template prompt for a feature, fix, review, test plan or codebase explanation.
    03 · MODELS & PRIVACY

    Local first, remote by choice

    • Local engine: the bundled synthetic stack exercises the integer WASM serving path.
    • Trained models: load the published M1 trunk from its public Hugging Face URL for top-8 next-token prediction.
    • API providers: OpenAI-compatible endpoints; prompts leave the device only after you configure and use one.
    • Downloads, hashes and tokenizer binding are verified before the worker receives an artifact.
    04 · LIMITS & HONEST STATUS

    What this is not

    • M1 is a language base with next-token prediction; no useful chat or agent capability is claimed.
    • The Studio does not modify the engine, worker, model-source manager or API client.
    • With no API provider configured, the agent cannot edit files on its own; it is a manual context-and-prompt workflow.
    • No external requests are made while the page loads. All remote contact is user-initiated.
