# Independent state bridge source review

Reviewed the Wick scratch state bridge, its finite test source, CUDA launch and nearest kernel, native integer pre-gate observer, shared reader writer, and draft sheet. Access was read-only. Held prompts and references were not opened.

**Held FIT withheld.** The build log observed during review failed on `cudarc::driver::Ptx`, `CudaContext::load_module`, and the new required `question_state_matches` field omitted from the `bvgk_device.rs` initializer. A successful admitted build and the actual finite receipt are prerequisites. The finite source checks CPU/CUDA equality on 16 same-suffix inputs, compares both CUDA arms against the native observer, compares the knockout with ordinary production evaluation, requires state changes under the intervention, and exercises the nearest-label tie rule. Its synthetic labels cannot establish that the trained states name useful lexical forms.

The parent payload is sliced from the carrier, rehashed and decoded into the announced nonpositional Relation snapshot. The normal integer path and bridge share the causal read before the joint pointer gate. The CUDA path returns the pre-writer read words and performs the nearest comparison. The zero target drives a diagnostic writer whose result is discarded. CPU code constructs identities, supplies frozen lexical labels, aggregates prototype votes, and executes the shared reply writer. Treat the result as a mixed CUDA/CPU diagnostic for pre-joint-pointer Relation state.

Require a sealed pre-launch manifest for source, executable, exact carrier, TRAIN tokens, mask, derived index and masked evaluation inputs. The index records TRAIN digests, but prediction currently checks only the index artifact field and basic structure. Require the masked affirmative writer control and the actual finite receipt before a held launch. Log structured per-step reader replay words from externally selected forms. The current strings name form and slot but omit the exact row address and original copy cursor needed to distinguish wrong source selection from a writer or stopping failure. Reply arrays already permit exact first-wrong and EOS comparisons after separate reference release.
