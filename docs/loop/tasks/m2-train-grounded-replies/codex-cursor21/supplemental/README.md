# Capture files and reproduction

`PANEL.md` states the design and reachability. `manifest.json` contains references and is not a writer input. `source-spans.json` is the pre-run native-tokenizer reconstruction. `dispatch.json` is the gold-free writer input. `records.jsonl` stores the exact UTF-8 bytes of each actual script, transcript and stderr as JSON strings; every unpacked file was compared byte-for-byte with its original, including empty or nonempty stderr. `PRESEAL.sha256`, `CAPTURE.sha256`, and `RECORDS.sha256` bind the pre-run plan, raw outputs, and packed records respectively. Raw files remain on Wick and locally; they need not also be committed when the records are retained.

The Rust tool under `tool/` calls the bound native tokenizer and actual client. It uses the same Cargo package and executable name as an earlier instrument. **Always give this tool its own target directory; never build it into the earlier form-ordinary target**, or Cargo can overwrite that instrument's executable. On Wick, from this panel's `tool` directory, build with `CARGO_TARGET_DIR=/mnt/plexpool/uor-r4-corpus/runs/20261121-codex-cursor-advance/OWNED-PANEL-target cargo build --release --offline`, replacing `OWNED-PANEL-target` with a unique directory for this panel. The source contains the exact pinned client, artifact and tokenizer paths. The `prepare` and `capture` modes write files and invoke the model respectively; do not rerun them when checking the sealed observation. Static checks of stored checksums and unpacked bytes are sufficient to verify the package.
