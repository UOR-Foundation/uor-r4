## What changed

- `m6_exact_arithmetic.rs`: a strict, original-byte-length-bounded parser for one unsigned decimal `+` or `-`, with a 160-byte limit, 10-digit operand bounds and explicit malformed, unsupported-shape, prompt-limit, overflow and subtraction-underflow errors. Original length is measured before trimming, so leading/trailing whitespace cannot bypass the bound. Full-input candidate/operator detection covers signed, leading-dot, operator-only, nested/alternate-grouped and date-prefixed forms, `%`, `^`, `*`, `/`, `×`, `÷`, and operators at or after byte 160. A leading operator-only minus is an explicit error. Pure ISO date/time including hour/minute, optional seconds/fraction, `Z` and positive/negative timezone offsets falls through; date-prefixed arithmetic remains an error. Ordinary prose, bare signed literals and no/one-sided-space subtraction fall through. Subtraction requires whitespace on both sides. Oversized operands report the 10-digit bound before parsing. Exact answers call `GeometricArithmeticEngine` and include actual carry/borrow records.
- WASM and browser worker: `exactArithmetic` returns structured JSON. A handled answer has no model token IDs, no model weights read, zero completion tokens and no `weightsPerToken`, `allocDelta` or `allocEvents` field. Local/API streaming and final renderers all display `0 model tokens · tool`, without a computed model rate, model stop reason or allocation delta. The original 32-token trajectory, save/restore and network traps remain intact.
- Tauri and OpenAI transport: `native_exact_arithmetic` shares the Rust function. `desktop_openai.js` returns a JSON fallback with `model: uor-chat`, `uor.tool: m6-exact-arithmetic`, empty completion IDs and zero usage; ordinary prompts retain the existing sidecar stream. Unsupported signed, grouped and overlong arithmetic returns explicit errors instead of synthetic generation.
- Conversation history: `apiMessages()` and `loadConversations()` preserve the exact-tool marker. The user prompt and assistant answer remain visible but are removed as one exchange from later OpenAI context, including after restore. This addresses the measured 81- and 212-position failures without increasing context limits or silently truncating ordinary history.
- Worker identity: live loads carry monotonically increasing operation IDs, including discrete responses. The worker uses an internal latest-load token and suppresses stale commits/errors. The page ignores stale numeric responses and clears capabilities/model metadata on a new load or current identity failure, disabling the composer. Missing filenames, missing/invalid hashes and valid-but-wrong 64-character digests fail closed with both full values reported on the real worker path. Typed-adapter checks remain independent of numeric message ID; unpinned loads require a valid lowercase digest. Legacy no-ID responses remain compatible only when identity matches and no new load awaits correlation.
