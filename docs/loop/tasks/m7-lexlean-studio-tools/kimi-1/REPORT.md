## What changed

- `m6_exact_arithmetic.rs`: a strict, 160-byte-bounded parser for one unsigned decimal `+` or `-`, with 10-digit operand bounds and explicit malformed, unsupported-shape, prompt-limit, overflow and subtraction-underflow errors. Full-input shape detection covers `%`, `^`, `×`, `÷`, nested and alternate grouping, and operators at or after byte 160 without skipping the limit. Subtraction requires whitespace on both sides, including after an instruction prefix. Ordinary prose, signed literals, ISO date/time shapes and no-space or one-sided-space subtraction fall through. Exact answers call `GeometricArithmeticEngine` and include actual carry/borrow records.
- WASM and browser worker: `exactArithmetic` returns structured JSON. A handled answer has no model token IDs, no model weights read, zero completion tokens and no `weightsPerToken`, `allocDelta` or `allocEvents` field. Local/API streaming and final renderers all display `0 model tokens · tool`, without a computed model rate, model stop reason or allocation delta. The original 32-token trajectory, save/restore and network traps remain intact.
- Tauri and OpenAI transport: `native_exact_arithmetic` shares the Rust function. `desktop_openai.js` returns a JSON fallback with `model: uor-chat`, `uor.tool: m6-exact-arithmetic`, empty completion IDs and zero usage; ordinary prompts retain the existing sidecar stream. Unsupported operators and overlong arithmetic return explicit errors instead of synthetic generation.
- Conversation history: `apiMessages()` and `loadConversations()` preserve the exact-tool marker. The user prompt and assistant answer remain visible but are removed as one exchange from later OpenAI context, including after restore. This addresses the measured 81- and 212-position failures without increasing context limits or silently truncating ordinary history.
- Worker identity: live loads carry monotonically increasing operation IDs, including discrete responses. The worker uses an internal latest-load token and suppresses stale commits/errors. The page ignores stale numeric responses and clears capabilities/model metadata on a new load or current identity failure, disabling the composer. Missing filenames, missing/invalid hashes and identity mismatches fail closed. Typed-adapter checks remain independent of numeric message ID; unpinned loads require a valid 64-character lowercase digest. Legacy no-ID responses remain compatible only when identity matches and no new load awaits correlation.
- Identity/package checks: staged `index.html`, `studio_api.js`, `desktop_openai.js`, `uor_model_worker.js`, WASM and JS compare against current source. Every manifest entry is hash-checked against its staged file and every external packaged `pkg/`/`models.json` resource is checked against the same bytes.
