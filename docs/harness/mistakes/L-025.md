## What happened

One day of card time, ~8.5 hours, of which roughly one hour produced everything that was actually
learned. The failures share one shape: **an expensive run started before the cheap thing that would
have interpreted it, or refuted it, existed.**

1. **A 32,768-step run (5.3 h) trained with a readout that was already known to be the defect.** The
   writer's port address admitted the target on 2.3 % of rows and picked it 0.4 % of the time; the
   centroid address on the *same weights* admitted 12.0 % and picked 8.1 %. The measurement that found
   this took **three minutes**, on a checkpoint that already existed, one day after the run started.
2. **The same run started before the instrument existed.** Its result was "nearest 15.70 % against
   T2's 15.99 %", which is uninterpretable: top-1 parity hid a **2.63-bit** deficit behind a bigram.
   Building `bits = mean log2(rank+1)` afterwards cost an hour and immediately produced the number
   that mattered. It should have come first, because it was one eval.
3. **A one-flag defect went unmeasured for 32,768 steps.** The token hinge's margin defaulted to 1.0
   against a score that is a mean over 512 lanes; the source says it "can never saturate". Setting a
   reachable margin was worth **0.94 bits and 30 % nearest at equal cost** — a 20-minute arm.
4. **Four instruments were trusted before being executed once.** A supervisor whose learning rate was
   empty (a zero-padded step number inside a Python literal), so the long run silently never started; a
   kept-cells A/B whose two arms produced *identical* numbers, so nothing was compared; a feedback arm
   whose batch and step count differed from its comparison, so its result was confounded; and the run's
   own resume path, which had never been run and was broken the first time it was.
5. **Unlike configurations were read as evidence, twice.** 656 ms (sheet objective, no table search)
   against 792 ms (`nearest`, table search) became "the kernel got slower"; a batch-48/4,096-step arm
   against a batch-24/32,768-step run became "the address hurt training".

## Why it costs

A run whose reading has no baseline is not a measurement, it is a booking. The card hours are real, but
the actual loss is that a decision gets made on the wrong quantity — top-1 parity instead of bits — and
then the project spends another day on the wrong lever.

## The rule

Before any run of 15 minutes or more:

1. **The instrument exists and has reproduced a known number.** No run reports a quantity that has never
   been checked against one already in the record.
2. **A same-rows baseline exists for that quantity.** A model's number with no count-table number beside
   it is not a result.
3. **One flag differs, and the saved configs prove it.** Read each arm's `config.json` back and assert
   the differing key; identical arms are a bug, not a tie.
4. **Multi-hour processes have had their resume path executed once**, on a 30-step case.
5. **Cost is quoted from a measured run**, never from optimism, and the reading it produces is named
   before it starts.

Anything compared across different steps, batch, data or objective is labelled **confounded** in the
record, and is not cited as evidence for a mechanism.
