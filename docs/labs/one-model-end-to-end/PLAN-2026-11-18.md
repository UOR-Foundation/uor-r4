# The plan: fix the math first, then scale (18 Nov 2026)

Owner's rule, stated here so no unit can ignore it: **nothing long runs until its cost has been
examined and attacked.** A 30-hour, $100 run that could be an hour after a math fix is a defect, not
a cost of doing research. The precedent is the read's 256× speedup and the serving kernels'
270 → 3,042 tokens/s — both were arithmetic, not patience.

The goal: **small, compact, frontier-level intelligence without transformers or their
inefficiencies.** That is a capability-per-parameter and capability-per-joule goal, not a
capability-at-any-cost goal. Every stage below is judged on that.

---

## Part 1 — The cost audit (do first, no GPU spend)

Before any of the gaps in Part 3 is attacked, every stage gets a measured cost at the current shape,
one row per stage, in `docs/labs/one-model-end-to-end/COSTS.md`. The stages:

| stage | what is measured | known now |
|---|---|---|
| training step | s/step at a named batch and context, and tokens/s | 12,288 tokens/step at 0.60 s = **20.5 k tok/s** (card free, before the route fix) |
| evaluation | s per 1 k scored rows | 101,175 rows ≈ **60 s**; 2.13 M rows ≈ **12 min** |
| export | s from checkpoint to artifact | ≈ **2 min**; artifact **8.2 MiB** |
| serving | tok/s on release, per shape | 25.5 tok/s is a **debug** build; the real figure is unmeasured |
| corpus | s per 100 M tokens tokenized | 385 M tokens ≈ **50 min** |
| tokenizer | s per 100 MB of text | 407 MB ≈ **3 min** |

**The gate:** a planned run is refused if any stage's *known* fix would cut its wall clock by more
than 20 %. The audit exists so that rule is checkable rather than a sentiment.

## Part 2 — The math fixes, in expected-win order

Each is "same outputs, less work", with a gate. None changes a model's definition.

| # | fix | why it is large | gate |
|---|---|---|---|
| **M1** | route + sibling precompute in the projection (**done**, unmeasured) | the route depends on the output block, not the row; it was walked per row in both directions | GPU/CPU parity (57 tests pass) + tokens/s |
| **M2** | writer's candidate inventory (537 M elements/step) scored on the cell's **centroid** over the width, or streamed | the inventory materialises 512 lanes per candidate to compare identities | identical picks on a fixed batch + tokens/s |
| **M3** | fuse the per-stage q16/exp conversion into the gather | ~2 M values × 72 projections a step, as a separate pass | bit-identical stages + tokens/s |
| **M4** | serving: score the writer's **kept cells** (≤ 16 × 32 = 512 rows) before the whole table (8,192 × 512) | the served nearest scan is 4.2 M MAC a token; the shortlist is 262 k | identical tokens on a fixed panel + tok/s |
| **M5** | evaluation: score a fixed-row subsample, never the whole held-out corpus | 2.13 M rows is 12 min for a reading that 100 k rows gives | the same verdict on both |
| **M6** | corpus: parallel shard encoding, and a 1 B corpus built **once** with its pins sealed | 385 M tokens is a 50-minute pipeline; 1 B is 2 h of CPU | throughput in tokens/s |

M1 is in. M2 and M4 are the same idea from two sides (compare identities, not full vectors) and are
the cheapest large wins left. M3 rides on M1's kernel.

## Part 3 — The capability gaps, in dependency order

| # | gap | the reading that closes it | cost after Part 2 |
|---|---|---|---|
| **C1** | does the trunk learn human text? | `nearest` above **T2's 15.99 %** on the held-out donor dev | ~2 h |
| **C2** | does the readout lose it? | `admitted` toward `nearest` (now 2.9 % vs 15.3 %) via `kept_cells`, then the centroid address | 1 h per arm |
| **C3** | does it follow an instruction? | the **196-item oracle panel** vs the copy control | ~10 min |
| **C4** | is the read's write big enough? | the hard copy at the trained gain, not ×16 | 1 unit |
| **C5** | does geometry hold per parameter? | top-1 at 4.5 M / 30 M / 100 M against **published dense scaling curves** (external reference; a dense control run is forbidden by D28) | 1 unit of analysis + the runs of C1 |
| **C6** | does it scale? | C1–C5 at 10–30× the values and 10× the tokens, with U2 measured | days, not hours — only after C5 |
| **C7** | can it be post-trained? | instruction SFT on the donor data, then a preference pass | 1 unit + a run |
| **C8** | is it agentic? | long context, tool calls, a harness | after C6 |

**The decisive one is C5.** If a 30 M-value geometric model is within a small factor of a dense model
of the same size on the same tokens, the gap to a frontier-class model becomes **money and data** —
which the owner has already said he will spend. If it is 10× behind per parameter, no scale closes
it and the answer is a richer transport, not more compute. **C5 is why the plan does not start at
scale.**

## Part 4 — The budget rule

For every run, before it starts:

1. **State the wall clock and the dollars** from the audit, not from optimism.
2. **Compare against the best known fix**: if a Part 2 fix cuts it by more than 20 %, the fix comes
   first — no exceptions for "it is already running".
3. **State what the reading decides**; a run whose result changes nothing is refused.
4. **Pre-register the threshold** before the run (as `codex-49` did for the writer diagnosis).
5. **A run that needs the card while another lab holds it waits, and is queued** — never killed, and
   never started on a shared card where its timing would be a lie.

## Part 5 — The order, now

1. **M1 measured** — the tokens/s of the route precompute, the moment the card frees.
2. **C1** — the 0.89-epoch run at the corrected recipe (`nearest`, `--lr 0.001 --lr-end 0`) against
   T2's 15.99 %.
3. **C2** — the clean `kept_cells` A/B at 4,096 steps, then the centroid address; both 1-hour units.
4. **C3** — the panel on the first artifact whose pick is not 0.8 %.
5. **M2/M4** — the writer's inventory and the served shortlist, as soon as C2 shows the address is
   the cause.
6. **C5** — the per-parameter analysis, which needs C1's numbers and no new GPU time.
7. **C6** — scale, with U2 measured and the corpus built once.

## What this plan refuses

- A 20-hour run before the step's cost is understood.
- A scale run before C5.
- A capability claim from a metric that a copy, an echo or a count table also passes.
- Killing another lab's work to free the card.
- "We will optimise later." Later is where the 100 dollars and 30 hours went.
