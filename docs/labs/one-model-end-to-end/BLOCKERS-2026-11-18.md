# The blockers, and the shortest path through each (18 Nov 2026)

Written after three read-only investigations of the project's own records: the training runs and the
objective, the read/transport line, and the export/serve path at a non-default shape. Every claim
below carries the record it came from. This file is the answer to "what is actually blocking us".

## 1. The objective and the schedule — the blocker that was self-inflicted

**`cell` on human text is a measured dead end.** `claude-295` ran it: loss flat at **1.0035**, and at
every width the arm was **behind its own TRAIN's unigram** (12,460–25,917 rows worse than always
guessing the commonest token). Our 18 Nov runs reproduced exactly that shape.

**The hinge has a degenerate equilibrium.** The address hinge asks a margin of 1 while the SpiralCore
roots are 0.5 apart, so it is never satisfiable; `claude-142` recorded the model **flattening its
ports until the hinge read exactly 1.0000**, after which the writer scored **345 where whole-table
nearest on the same checkpoint scored 7,813**. A dev hinge pinned at 0.99–1.00 is that equilibrium.

**The learning rate:** the trainer has one schedule, linear from `lr` to `lr_end`, and **no warmup**.
The CLI **defaults to a constant 2e-3** — the value that collapsed a run to 1,545. Every run that
improved used **decay to 0**.

**There is exactly one generalization result on human text.** `claude-301` (b64L): `nearest`, batch
64 / micro 16, `lr 1e-3 → 0`, 16,384 steps = 201 M positions over 28 M tokens →
**22.7 % / 23.4 %** next-token top-1 against T2's **17.6 %** on 1,460,697 held-out rows, and **ahead
on unseen rows** (+56,353 / +64,841). That is the recipe to copy, and the 18 Nov run now uses it.

**Caveat on the headline numbers:** M1's 7,002/14,287 is a **19-table lookup**, not the trunk (2,988
→ 7,002 is table growth); "beats T2" means "is a better count table"; 75 % of DEV replies are
verbatim TRAIN. No existing number contradicts "the trunk has not learned human text well yet".

## 2. Export and serve at 8,192 × 512 × 12 — closer than expected

- **The artifact is shape-driven.** The snapshot carries `vocab, width, mlp, context, kept_cells,
  layers`; the container parses and validates them; every table is length-checked against the shape,
  not a literal. **Serve needs no code change.**
- **No bound is hit.** Token table 8 MiB, routes ~21 KiB, gains ~135 KiB; artifact ≈ **8.5 MiB**
  plain. The 1 GiB candidate-vector bound only affects the float scorer, chunked at 2,048 rows.
- **Three producer refusals block the export path**, all in the float side:
  1. `fbs_export.rs:715–730` refuses a Hamming read whose readout layer ≠ **6**;
  2. `fbs-snapshot.rs:329–346` refuses any readout at **context ≠ 192**;
  3. `format.rs:347–357` refuses width 512 with **4** Hamming heads (head width 128 > 64) — 8 heads
     are required.
- **Silently wrong at another shape:** the memory key window and Q31 sidecar are pinned to 192.
- **Our current run has no Hamming read** (`--hamming-read 0`), so a plain snapshot → export is
  likely to work today; only the readout/panel paths hit (1) and (2).

## 3. The writer's admission — a separate defect, with a known root

Admission failed at seed 2 (**493 against 6,909 nearest**), so the served decoder is whole-table
nearest. Its degenerate root is the same unsatisfiable margin as §1: the model flattens the ports to
satisfy it. This is the **readout** defect, not the read's.

## 4. The read/transport — proven find, missing write

- **Finds it:** first pick right on **1,000/1,024** and **990/1,024**.
- **Writes 2.6 %** of the stream (`|p|/|x|` 0.026; 0.0017 at 4,096 steps).
- **×16 passes** (0.984/0.969, 0.969/0.965) with decode-to-self on every first-right row; at ×1 it
  gives 0.631/0.643 and 0.096/0.145.
- **Cutting the read returns 0.000/0.004** — the read is the whole effect.
- **The native operator is done and exact** (1,024/1,024 picks, 0 clips, CPU = CUDA on 49,152 rows).
- **Open:** the trained gain (needs a native downstream loss; none exists), and whether one fixed
  gate family can express the *other-fact* rule — the registered unlock is a **host probe** of the
  best reachable `chose_other`, no GPU.

## 5. Data and capacity

The model learns its own templated text (7,676/14,287 against T2's 6,302) and not human text. The
trunk holds 64,000 learnable numbers against the table's 1,048,576, and the capacity sweep found **no
arm still rising**. Data is not the first lever; the objective and the readout are.

## The order

| # | unit | why now | cost |
|---|---|---|---|
| 1 | **`nearest` + decay-to-0 + b64L batch** on the 8k corpus | the only recipe that generalized on human text | ~4 h, **running** |
| 2 | **export the checkpoint and score the 196-item panel** | the capability, not the precondition; plain snapshot likely works with no Hamming read | 1 h + 1 h |
| 3 | **writer admission** (unsatisfiable margin → flattened ports) | the readout defect that wastes a working representation | 1 unit |
| 4 | **read's trained gain** + **host other-fact probe** | claude's line; the write scale is the measured gap | 1–2 units |
| 5 | **only then** 1 B scale, with **U2** (route precompute) first | 61 h → ~20 h | 1 unit + the run |

**What is not on this list:** more data, a bigger model, a dense baseline (D28), or another read
rewrite. Each of those has been measured or forbidden, and none is the current blocker.
