# Model-gate coverage audit (18 Nov 2026)

The Cleanroom review said the project "proves a gate *can* fail but never records what fraction of
injected defects its gates catch". **The first half is wrong and the second half is right.**

## The practice exists, and the runner is stricter than the review assumed

`docs/harness/gates.json` registers **12 gates**, and **all 12 carry a planted break**:

    { "id", "proves", "command", "reads", "quick", "break": { "file", "replace"|"append", "expect" } }

`crates/uor-r4-harness/src/loopgates.rs` runs each gate, plants its break in a scratch copy, re-runs,
and fails with **"the gate stayed green with its break planted: add the case"**. Results go to a
ledger (`local/<lab>/gates.jsonl`). That is exactly the detection-rate practice, implemented and
enforced.

**The gap is coverage, not machinery.** The 12 registered gates are all process, formatting or docs
gates: `stack-contract`, `fmt-claim-wording`, `fmt-harness`, `claim-wording`, `loop-gates-watch`,
`loop-drive`, `loop-next-sources`, `loop-next-wait`, `loop-next-owner-direction`, `git-hooks`,
`loop-migrate`, `loop-review-changes-blocks`.

**Zero of them is a model gate.** Not one covers the readout, the writer, the artifact, the corpus or
the panel — which is where every defect of the last week actually occurred.

**Two of the three failures in this record are checks that were never once executed** — bar 4b's
control and the run's resilience path. That is the same failure mode the runner's message names, and
it is the argument for registering these gates rather than trusting that they exist.

## The four gates to register, with their breaks

Each is written to the existing schema, so `loop gates` will run it and plant its break. Ordered by
how much they have already cost when absent.

1. **`run-continuation`** (missed twice, ~2.5 h). Command: the supervisor's own `--init-from`
   smoke test — a 30-step run, then a 2-step continuation, asserting the continuation's step-0 dev
   equals the first run's final dev. Break: pass a checkpoint from a different seed; expect the
   resumed dev to differ from the first run's final dev.
2. **`writer-chunk-equivalence`** (uncertified change). Command: a writer test comparing column-chunked
   `candidates` scoring against the one-shot computation on a fixed small table. **This test does not
   exist yet** — M2's correctness rests on a hand run. Break: drop the last column from the chunk loop
   (`count - start` → `count - start - 1`); expect the comparison to differ.
3. **`bit-identity-step`** (the strongest certificate, unregistered). Command: the step-8,192 dev
   numbers on the pinned checkpoint. Not `quick` — it costs a run — but it is the one check that
   decides whether a kernel edit is lawful.
4. **`panel-census`** (cheap, and it protects C3). Command: recount the frozen panel
   (196 = 132 + 64) and refuse if the census moved. Break: change one item's expected kind; expect
   the recount to disagree.

**Constraint recorded while writing this:** `native_vector_writer.rs` and
`spiralcore_fbs.cu/.rs` are part of a checkpoint's source-hash binding, so gate 2's test must be added
in a file outside that set while a run is in flight, or the run's checkpoints become unexportable.
That is why gate 2 is specified and not yet written.

## What this changes

The review's recommendation — "publish breaks-caught/breaks-made per line" — is adopted, but its
subject is narrower than it claimed: the ledger exists for process gates and needs **five model
gates**, two of which are the two failures in this record.
